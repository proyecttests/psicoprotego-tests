# Clinical Landing Writer — filosofía

## Por qué existe

Psicoprotego apuesta por autoridad clínica visible (E-E-A-T en
terminología SEO) como vía de crecimiento de `psicoprotego.es/tests`.
Para ello cada landing de test necesita:

- Redacción técnica y cercana, coherente con `/servicios/*`.
- Validación científica visible con referencias verificables (DOI).
- Autoría clínica firmada (colegiación, universidad, perfil).
- Limitaciones honestas (cuándo NO sirve el test).
- Disclaimer clínico sin alarmismo ni marketing.
- Privacidad explícita.

Redactar esto a mano por Cristina y Emmanuel para cada test
escala mal (múltiples tests planificados). Redactar con IA sin
revisión clínica es peligroso (YMYL: Your Money or Your Life —
Google penaliza fuerte y pacientes reales pueden tomar decisiones
basadas en el contenido).

Este skill es el compromiso: generación asistida con rigor, siempre
con humano clínico firmando tras revisión.

## Inspiración: Naturalizer de inforeparto

El Naturalizer optimiza contenido para E-E-A-T en monetización
(inforeparto.com, afiliación, tono coloquial). Heredamos de él:

- **Pipeline multi-fase** (research → draft → review).
- **Checklist de naturalidad** (detectar frases-IA típicas).
- **CompetitorAnalyzer** (aquí adaptado: análisis de landings
  competidoras tipo `psicologiayllanura.com/test-gad-7` para no
  producir copy plano).
- **ExperienceDB** (aquí adaptado: contexto clínico repetido
  en tests relacionados, como el bloque de privacidad).

Divergimos en:

- **Registro clínico estricto vs coloquial.** No se permite
  lenguaje emocional, hype, ni frases tipo "descubre si tienes
  ansiedad". Siempre "evalúa orientativamente tu nivel de".
- **Compliance YMYL.** Disclaimers, limitaciones, referencias
  bibliográficas, crisis handling.
- **Autoría real firmada, no genérica.** Cada test tiene autor
  y revisor de `authors.json`, visible en el contenido.

## Principios rectores (jerárquicos)

1. **Seguridad clínica.** Nunca promete diagnóstico. Nunca oculta
   limitaciones. Nunca sustituye evaluación profesional.
2. **Honestidad epistémica.** Lo que se sabe, se cita. Lo que no,
   se reconoce. Nada de afirmaciones gratuitas.
3. **Utilidad para el usuario final.** Cada sección responde a
   una pregunta real que una persona se hace al llegar.
4. **SEO y E-E-A-T.** Pero siempre al servicio de los tres
   principios anteriores, nunca por encima.
5. **Consistencia editorial con `/servicios/*`.** Voz, estructura,
   tono.

## Métricas de éxito del skill (no del contenido generado)

- **Ratio de revisión humana.** Número de `[REVISAR]` resueltos
  con cambio vs sin cambio. Si Cristina y Emmanuel aceptan 80%
  de borrador sin reescritura, el skill funciona.
- **Tiempo de revisión por test.** Objetivo: <60 minutos de
  revisión clínica por test.
- **Adopción en nuevos tests.** Si cada test nuevo se redacta con
  el skill y no manualmente, el skill es adoptado.
